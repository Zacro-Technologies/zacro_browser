# Native Chromium and extension parity

Runtime pinned to Chromium `156.0.8078.48` (`d0c02bfad08ec92a6ffcf989e53cd995e6381a4c`) and CEF `4fa4ab516dac`. The application shell is Swift/AppKit/SwiftUI; Chromium remains its native browser engine.

## Implemented host integration

- Retained Chrome-style documents and isolated persistent/incognito request contexts; no Alloy or WebKit substitution.
- Process-local DevTools JSON calls, bounded responses/deadlines, cancellation, isolated-world extraction, and authenticated document resource requests through the document's actual CEF request context. No debugging socket or privileged webpage binding.
- Native downloads, control callbacks, HTTP authentication sheets, permission decisions, printing, Inspect Element, Chromium image-copy/context menus, selection search, and link/background-tab/Peek commands.
- Browser/window termination and beforeunload cancellation, asynchronous service shutdown, profile retirement journaling before safe database removal, and retained document promotion.
- Real Chromium popup adoption retains its actual document and opener. Packaged acceptance verifies opener references and callbacks; POST/OAuth and named-window reuse still require extension fixtures.
- Extension registry/permissions/enabled state/pinning/icons/options/commands/reload/install/update/uninstall operate against Chromium's trusted internal management document. Structured Chromium errors propagate to the native UI.

## Custom runtime source and build

Official pinned `automate-git.py` preparation has completed under `/Users/takamimarsh/Developer/zacro-chromium`. It uses shallow history and arm64 only. The source checkout and tools consume approximately 35 GiB; 103 GiB remained before compilation. `CefSwift/NativeRuntime/build_runtime.py` builds Release only, without debug symbols, at four jobs, checks a 65 GiB starting budget and stops its own process group below 15 GiB free. It never removes user files.

`NativeRuntime/apply_adapter.py` validates the exact CEF revision and original source, produces `native-adapter.patch`, and refuses unrelated edits. It permits upgrading only its exact prior generated output. `apply_storage_adapter.py` separately patches the pinned Chromium storage backend with provenance events and atomic conditional remote updates. GN generation passed 36,614 targets. The adapter and all four modified atomic storage backend objects compile successfully using GN's exact compiler commands and official generated headers; reports are under `macos/.build/verification/native-objects` and `native-storage-objects`. Compilation of the other modified integration objects and full Chromium prerequisites continues. Apple's required Metal toolchain is installed. Successful object compilation does not constitute a linked framework or runtime validation.

The adapter adds a native-only browser protocol session, document audible/capture/unload/DevTools/download safety state, asynchronous profile site-data/cache removal, and Chrome's own serialized navigation entries for real back/forward restoration. Navigation envelopes use a fresh AES-GCM key wrapped by Chromium OSCrypt and authenticate the full originating profile path. The version-two envelope is bounded to 6 MiB. Restore requires a fresh initial document or the exact blank entry retained by native discard. Safe discard keeps the same native tab identifier and retains an in-memory history for immediate wake; private page state never leaves that memory. Legacy URL/title-only import uses validated entries through NavigationController.

Native extension action dispatch validates the installed action and its toolbar container before invoking Chrome's real `ToolbarActionViewModel`, including activeTab permissions. This also avoids upstream `Extensions.triggerAction` dereferencing a missing toolbar action. The adapter provides per-tab badges/icons, context-owned registry observation, verified Web Store installation with Chromium's native permission UI, and direct StorageFrontend observation. Storage snapshots carry an installation nonce; remote updates require that nonce, an exact expected storage baseline, a causal origin tag, final-state quota validation, and a single backend WriteBatch. Private-origin mutations are excluded from synchronization. Stock CEF returns unsupported-method errors for these methods; selecting Chrome runtime alone does not enable them.

`apply_topology_adapter.py` adds native hooks after ExtensionFunction pre-run validation and before EventRouter dispatch. The CEF adapter registers real Chrome SessionTabIDs against the Swift model, queues extension startup queries until the native host observer is present, validates official API schemas, normalizes navigation through ExtensionTabUtil, and checks caller/profile/installation identity before host mutations and completion. Tab and window responses are parsed using Chromium's generated types and scrubbed with Chromium's permission rules; URL/title query matching happens after redaction. Physical implementation-window events are suppressed and logical host events use the real EventRouter. Zoom and capture operations remap their logical target and continue through the original Chromium implementation. These source changes are gated by `extensionBrowser` and still require compilation and extension fixture execution.

Storage mutation observations retain the actual writing Extension object, preventing an old asynchronous write from being assigned a replacement installation's nonce. A separate incarnation identifier derives from Chromium's first-install preference, which persists through updates and is deleted at uninstall. Private profiles intentionally have no extension integration, matching the Electron manager's explicit private-profile exclusion; their independent ephemeral contexts are not silently linked to a persistent profile.

The packaged UI review found retained-page accessibility disappearing after tab switching. Enabling Chromium renderer accessibility retained the actual native accessibility tree across the same interactions. The custom CEF source owns a scoped per-WebContents accessibility lease. Matching official debug symbols identify the old teardown watchdog stack as Chromium's `BrowserProcessIOThread::ProcessHostCleanUp` waiting for NetworkService exit. Swift CEF client-handler ownership cycles and several transferred-reference leaks were subsequently fixed; two ownership tests pass, and three expanded packaged shutdown runs exit zero. The original longer GUI sequence remains a release gate until repeated.

Dormant restored tabs reserve actual `SessionID::NewUnique()` identifiers without creating native windows or renderers. An unguessable, profile-bound, single-use token is claimed before CEF browser creation and consumed before SessionTabHelper construction. The helper adopts the reserved ID before it becomes visible, never changing an existing native ID. The token is removed from internal extra-info dictionaries before renderer propagation or popup inheritance. Logical snapshot/query publication therefore need not materialize every saved tab. These source hooks and the host integration still require full custom-runtime acceptance.
