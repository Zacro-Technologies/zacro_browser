## Durable state

`SessionPersistence` serializes snapshots on one utility queue. App callers opt in with `enableDebouncedPersistence()`; saves coalesce at 250ms with a one-second maximum deferral. `flush()` cancels deferred work and synchronously writes the latest snapshot behind all older queued writes. The application must call it before termination.

`commit` normalizes a separate candidate, writes it synchronously, and only publishes the candidate after success. Theme/onboarding/import dialogs can keep the draft open on disk failure instead of claiming a successful save. Collection and HTML imports use this path and cannot publish a partial import.

Files use exclusive 0600 temporary files, fsync, atomic rename, and directory fsync. A valid prior file becomes the backup. A corrupt primary is preserved under a generated unreadable filename and a valid backup is recovered. Explicit history/archive/permission/profile clears use throwing durable transactions. They sanitize the backup and managed unreadable recovery files before committing the primary, and publish memory only after success. A blocked recovery write preserves the previous primary and in-memory state; unrelated files are untouched. Private profiles and their dependent collections are removed from all persisted snapshots.

`BrowserStoreTests` and `ElectronParityTests` cover 51 cases as of 2026-11-01. Tests include queued-write ordering, flush, privacy clearing after an outstanding write, backup recovery, failed editor commits, failed collection imports, private profile destruction with an unwritable public store, and shortcut/site-search editor rollback. `SpaceGestureTests` adds 19 clock-injected scenarios, including the 18 Electron cases. They verify quick flicks select exactly one neighbor, held contacts never time out, long drags can span the strip, reversal discards old velocity, and momentum cannot contribute distance or cause a second commit. An additional device-switch regression verifies a completed trackpad stream cannot lock out a subsequently used mouse. `NativeExtensionQueryTests` adds nine query validation and matching cases, including strict splitViewId matching, for 79 Core cases. These are state-level tests. Native engine back/forward, actual drag hit testing, physical trackpad feel, AX, and screenshots belong to the runtime acceptance suite.

## Integration contracts

`BrowserRepository` owns the sole persistence writer. `canonicalStore` exposes all tabs and the focused window's selection for shared services; `store(for:)` projects one window's tabs and selection while forwarding mutations to a fresh authoritative reducer. Façades cannot save a directly modified or stale snapshot over another window's work. Shared profiles, Spaces, folders, settings, history and bookmarks stay in the repository. Each live tab belongs to exactly one window; favorites remain shared across that window's Spaces. Cross-window transfer expands a split to both members without changing either document identity.

Window creation writes its URLs, initial bounds and ownership in one durable commit. Closing a public window parks its session for restoration; empty parked sessions do not consume the 100-open-window limit. A private profile is destroyed from memory when no open window retains it, even if public disk storage is unwritable. Ten repository cases passed with the existing 79 Core cases on 2026-11-02; a subsequent download restart regression also passed, bringing the Core suite to 90 cases. Evidence is stored under `macos/.build/verification/core-window-tests-fourth.log` and `core-download-restart.log`. Actual AppKit window transfer and Chromium extension events require the separate integrated acceptance build.

Tab groups preserve each member's Space assignment; the sidebar presents the current Space's subset. Group and ungroup operations expand split partners, and grouping clears favorite/pin/folder classification without destroying existing folders. Pinned tabs precede ordinary tabs in the same canonical profile/window order used by extension indices. A whole-group window transfer retains its UUID; a partial transfer detaches the moved members. Invalid, empty, cross-profile and cross-window memberships are repaired, and portable import remaps group identities. Eight group cases plus the prior cases passed in the full 98-case Core run on 2026-11-02 (`core-services-post11.log`).

The post12 run passed **115 Core and 64 Services tests** with no failures or skips (`macos/.build/verification/core-services-post12-full.log`). New cases cover native bookmark migration acknowledgements and recovery copies, account/local UUID identity, approved URL persistence without importing authority, history-clear/pin-reset/duplicate provenance, explicit saved-window reopening, atomic archived/retained/parked tab restoration, and download GUID restart behavior. The tests validate model contracts; actual Chromium bookmark events, extension sessions and native navigation permission checks remain integration gates.

`NativeNavigationProvenance` is a record of a native approval, never permission to load. Before using a retained native URL, the application must ask Chromium to revalidate the same installed extension incarnation and exact destination under its current policy. The Core structural limit is 1MiB for approved destinations; ordinary typed/imported web addresses keep their existing limits. Portable export excludes privileged current and saved URLs, and portable/native snapshot imports discard provenance. Navigation history, duplicated tabs, saved pins and history clearing preserve a matching receipt for that later native validation.

`savedWindows` exposes retained public windows in closure order. `reopenWindow(id:)` preserves ownership, selected tabs, highlights and split groups without creating a new blank page. `restoreSessionTabDurably(id:)` restores an archive entry or closed retained pin, or transfers a tab and its split partner from a parked window, in one durable commit. Live foreign tabs and cross-profile restores are rejected. Closing retained pins continues the original saved-destination reset behavior. `DownloadRecord.nativeGUID` binds native records across restarts; `canResume` resets until a new native snapshot confirms it, while the persisted danger flag continues to prevent unsafe presentation actions.

Peek is also projected as a virtual live document with logical ID `peek:<sourceID>`, owner/profile/source opener and stable metadata, without adding another persistent tab. `SavedPeek` retains navigation approvals/history, mute/discard settings and whether the overlay is presented. Explicit extension selection of the source hides the retained overlay; normal sidebar selection reveals it. Durable promotion preserves its metadata and remaps tabs opened by that Peek to the promoted identity. The host still has to preserve the actual Chromium ID and WebContents during promotion. `selectTabs(...presentPeek:)` can atomically choose the underlying document alongside highlighted tabs. Five model tests cover legacy decoding, selection/restart, promotion, rollback, safe imports and virtual opener lifecycle.

`DownloadCollection` retains active, paused and resumable downloads ahead of completed history within the 1,000-record Library bound. Complete native snapshots can remove an absent GUID only in their profile and only if no event advanced its revision during the read; truncated snapshots never imply deletion. Four regressions cover that merge policy and real store normalization. The final post13 run passed **124 Core plus 64 Services tests**, with no failures or skips (`core-services-post13-full.log`). Actual extension/Peek identity, popup anchoring and native download fixtures remain runtime acceptance work.

The session restore transaction also accepts a virtual Peek from a parked public window. It transfers the source and any persistent split partners, selects the retained preview, and preserves its identity without promoting or duplicating it. Two additional cases verify restart, live/missing/cross-profile rejection and failed-write rollback; all five `BrowserSessionTests` passed (`sessions-peek-post13.log`).

Window sidebar moves now resolve their projected insertion neighbor against the authoritative shared collection, so a second window's drag cannot be interpreted as an index among every window's tabs. A regression covers middle reordering, favorite creation, dragging back out and restart while preserving the other window's order. Startup policies apply to every saved window: disabling session restoration retains pins, splits and Peeks without selecting them, while a standalone selected pin remains dormant on restart. An intentional empty selection survives subsequent normalization and persistence; an invalid nonempty reference still repairs. Shared Space deletion moves every affected window to the remaining Space in that window's original profile. - Call `sidebarTabs()` for keyboard tab ordering instead of independently sorting categories.
- Use atomic `moveTab(..., pinned:, favorite:, clearFolder:)` for drag classification. Omitted folder means preserve it; `clearFolder: true` means remove it.
- User address entry uses `BrowserAddress.resolve`. Only a verified extension action should call `createExtensionTab`/`setExtensionPage`.
- Theme/onboarding edits use `try commit`. Profile/folder creation uses `createProfileDurably`/`createFolderDurably`; shortcut and site-search edits throw on persistence failure. Privacy controls use `clearHistoryDurably`, `clearArchiveDurably`, `clearPermissionsDurably`, `removePermissionDurably`, and `deleteProfileDurably`; legacy wrappers expose failures through `lastError`.
- `discardPrivateProfile(id:)` destroys the private profile and dependent in-memory records without a public disk write; use it when its last private window closes.
- Automatic memory sleep must honor `autoDiscardable != false` and revalidate after asynchronous checks. Explicit sleep/close and the separately chosen archive cadence remain user actions.
- Window bounds require Application capture/restore; the model alone does not reposition windows.
- `archiveCandidates(now:excludeIDs:)` is a pure query for runtime safety checks. Requery after asynchronous page checks before closing; `recordVisibleTabActivity(now:)` updates both visible split members, and departure/unsplit/close refresh their idle dates.
- `SpaceGesture.Input` uses seconds and semantic direction (negate native wheel deltas). Pass native contact phases and profile ID; preserve unknown momentum as `nil` for phase-less devices. Only `didRelease` selects a Space; `progress` drives continuous signed strip displacement. Native contacts own their release deadline, so a fallback timer must not finish an active contact.
- A release build still needs actual engine/UI acceptance and signed distribution validation. Passing these tests is not a release certification.
