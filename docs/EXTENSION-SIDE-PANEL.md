# Extension side panels

Zacro supports `chrome.sidePanel` in trusted managed extension pages and backgrounds with the `sidePanel` permission. The supported methods are `getOptions`, `setOptions`, `getPanelBehavior`, `setPanelBehavior`, `open`, `close`, and `getLayout`. Promise and callback calls use the existing authenticated native runtime facade. `getLayout()` returns `{ side: 'right' }`.

`side_panel.default_path` establishes the global default. `setOptions` may change its packaged relative `path` and `enabled` flag, or set a tab override with the native `tabId`. Global options and `openPanelOnActionClick` survive restart in the managed profile directory. Tab overrides and current open state last only for the owning native tab/extension generation. Profile data is isolated; private profiles do not run extensions.

Open a configured panel with **Manage extensions → Open side panel**, or enable `openPanelOnActionClick` and use the extension action. Programmatic `open({ windowId })` or `open({ tabId })` requires a recent genuine input event recorded by the host in the extension's own visible view, or a host action click. A gesture is consumed when opening; calling `open` from a script, including `executeJavaScript(..., true)`, cannot manufacture the host gesture. No temporary host permission is fabricated.

The panel is an actual sandboxed `WebContentsView`, attached beside the current page inside the existing right-hand shell panel. It does not replace or reload the page. The shell supplies the title and close button, computes bounded geometry from trusted layout IPC, and detaches the native panel during browser dialogs. Library, AI, Settings and extension panels share this one region. The view has its extension session, context isolation, web security, and no Node access. Navigation is limited to packaged pages belonging to the same extension; compatibility transport and service pages are reserved.

Global panels survive same-profile tab changes. Tab-scoped panels close on tab switches; closing, replacing, disabling/removing, profile changes and expired generations destroy their old native view. `close` only affects the caller's own matching panel. Foreign, closed, inactive-tab and hidden-profile targets are rejected. Browser window creation, alternate side placement, browser sidebar persistence across restart, and side panel events are not provided.
