# Internal integration contract

The desktop application uses CommonJS on Node/Electron and plain ES modules in its isolated UI. Remote pages have no application bridge. `src/main/main.cjs` is the entry point; `src/main/preload.cjs` exposes only `window.zacro.invoke(action, payload = {})`, `window.zacro.onState(callback)`, `window.zacro.onEvent(callback)` (both return unsubscribe functions), and `window.zacro.platform`.

`src/core/store.cjs` exports `BrowserStore`, `normalizeAddress`, and `createInitialState`. `new BrowserStore(directory)` loads state. `.state` is the current state, `.dispatch(action,payload)` applies a synchronous mutation and returns a result, `.snapshot()` clones the current state, `.save()` persists atomically, and `.flush()` is available on quit. `.on('change', callback)` notifies subscribers. The main process may update `.state` then call `.changed()` for runtime-managed downloads/extensions. State is JSON serializable.

Persistent state remains version 1 and contains profiles, Spaces, tabs, folders, history, bookmarks, archive, downloads, extensions, permissions, settings and window bounds. `createInitialState` and hydration in `src/core/store.cjs` own the complete shape and defaults. Times are epoch milliseconds; the initial profile/Space IDs are `default`/`home`. Startup has no tabs and `activeTabId` is null. Opening the command palette does not create a tab; explicit tab creation and the optional home page use `zacro://newtab`. Current defaults include a 12-hour Today archive, 224px sidebar, 336px panel and 20-minute pinned sleep; profile archive overrides and validated layout/shortcut settings persist.

Core mutations (payload keys): `tab:create {url?,spaceId?,active?}`, `tab:activate {id}`, `tab:close {id}`, `tab:pin {id}`, `tab:move {id,spaceId?,folderId?,index?}`, `tab:update {id,url?,title?}`, `tab:restore {id?}` (archive), `tab:archive-stale {now?}`, `space:create {name,color?,profileId?}`, `space:update {id,name?,color?,icon?}`, `space:activate {id}`, `space:delete {id}`, `profile:create {name,private?}`, `profile:delete {id}`, `folder:create {name,spaceId?}`, `folder:update {id,name}`, `folder:delete {id}`, `bookmark:toggle {url?,title?,profileId?}`, `bookmark:delete {id}`, `history:add {url,title,profileId}`, `history:clear {profileId?}`, `archive:clear {profileId?}`, `settings:update {values}`, `permission:set {profileId,origin,permission,allowed}`, `permission:clear {profileId?}`. Create returns the created record. Other mutations return null or the changed record. Explicit Close retains a Favorite or Space pin as closed metadata and releases its native page after the unsaved-work decision; ordinary tabs enter the archive. Unpinning a closed pin removes it. Never automatically archive pins or Favorites. Deleting last profile/Space is rejected. Move tabs only within same profile.

Main-process actions also include `state:get`, `navigate {url}`, `back`, `forward`, `reload`, `stop`, `window:minimize`, `window:maximize`, `window:close`, `layout {sidebarWidth?,panelWidth?,overlay?,peek?}` (UI sends overlay=true for dialogs to hide native web views), `find {text,forward?,findNext?}`, `find:stop`, `zoom {delta? reset?}`, `print`, `devtools`, `split:toggle {id?}`, `peek:open {url}`, `peek:close`, `peek:promote`, `download:show {id}`, `download:cancel {id}`, `download:pause {id}`, `download:resume {id}`, `download:rename {id,name}`, `download:undo {id}`, `data:export`, `data:import`, `data:clear {profileId}`, `extension:install`, `extension:remove {id}`, `extension:toggle {id}`, `external:open {url}`, `app:about`.

Snapshot extends store state with `runtime:{page:{loading,canGoBack,canGoForward,error?,zoom?},splitTabId:null,peek:null|{url,title,loading},platform,version,aiConfigured:false,aiBusy:false}`. Runtime may include `pages` map keyed by tab id. Host sends state via `zacro:state` and events `{type,...}` via `zacro:event`. Event types: `command {mode?}`, `panel {panel:'history'|'downloads'|'bookmarks'|'settings'|'ai'|'archive'|'extensions'}`, `find`, `toast {message}`, `ai:answer {answer,sources:[{url,title}],...}`, `ai:error {message}`, `ai:progress {message}`. UI handles initial state via `state:get`. Keyboard shortcuts work both in remote contents and shell.

AI service at `src/main/ai.cjs` exports `AIService`: constructor `{getState, getPageContext: async(ids)=>[{id,title,url,text}], emit:(event)=>void, userDataPath, openExternal, client?}`. `.handle(action,payload)` supports `ai:login`, `ai:login-cancel`, `ai:configure {model}`, `ai:disconnect`, `ai:ask {question,tabIds?:[],usePageContext?:boolean}`, `ai:cancel`, `ai:reset`, `ai:status`, and `ai:suggest-name {id,name,url,title}`. The `ai:status` action refreshes the connection. `.status()` exposes cached connection availability, configured/account/model state, login progress and request state; tokens are never exposed. `.latestSources` contains validated evidence URLs; the host handles `ai:open-sources` with active-profile checks and tab reuse.

The main-process `CodexClient` in `src/main/codex.cjs` owns the pinned app-server over stdio, a Zacro-specific home/workspace and OS keyring credential entry. Sign-in opens the validated official ChatGPT authentication URL through `openExternal`. API credentials and legacy credential imports are rejected. Inference occurs only after an explicit question or filename request; no automatic page sharing. Shared tab IDs must belong to the active, non-private profile. Research enables hosted web search; page/PDF questions and filename suggestions disable it. Threads are ephemeral and both thread/turn calls explicitly select no execution environments, with never-approve/read-only restrictions and fail-closed tool handling. UI provides sign-in, cancel sign-in, refresh, model choice, disconnect, research/current-page/selected-tab context, follow-ups, stop, reset and source opening. Live account acceptance is separate from mocked protocol verification; there is no API billing fallback.

## Interface additions in 0.2

Tabs may carry `customTitle`; an explicit user rename controls the displayed `title` while the native document title remains available for history/context. Window bounds also retain validated monitor coordinates and `maximized`. Old version-1 state remains compatible.

`runtime.pages[id].favicon` is a bounded, optional PNG/ICO data URL from `FaviconLoader`, never an external image URL. `savedFavicon` supplies a pin’s saved destination icon; `runtime.savedPeeks[sourceTabId]` supplies parked preview icons. A separate, bounded local cache preserves saved icons across restarts without adding raster bytes to portable browser state. Private icons remain memory-only. The `page:backdrop {frames:[{bounds,dataUrl}]}` event carries temporary PNG presentation frames while a modal is open; an empty frames array clears them. Consumers must reject late frames when no modal is open and must not show frames in private profiles.

`focus:chrome` asks the renderer to focus its address control; `page:focus` is a shell-only action to return focus to the active native page. F6 uses this cycle. The shell handles composition events and dialog focus locally. Native layout is calculated in `src/main/layout.cjs` using the current content top, sidebar/panel widths and validated page gutter. A hidden sidebar sends width 0. The renderer and native extension panel must agree with this layout, including at minimum window size and during rail resizing; shell menus and dialogs must not remain behind a native child view.

## Interface additions in 0.3

The current default sidebar width is 224; saved validated user widths remain valid. The renderer handles `sidebar:toggle {fromPage}` and returns focus through `page:focus` when the shortcut originated in a native page. Library is a compact chooser whose panels share section navigation and preserve their opener for focus return. Settings uses persistent disclosure state. Dialog and panel entrances are short; dismissal and native-view geometry updates are immediate.

## macOS integration

The host's `src/main/mac.cjs` defines native window chrome, the menu template and Mac shortcut mapping. Runtime snapshots include `fullScreen` and `focused`; the renderer exposes `data-platform`, `data-fullscreen` and the platform's shortcut labels. macOS uses native traffic lights with `hiddenInset` and reserves their area in the sidebar. ⌘S hides both sidebar and navigation strip, hides the traffic lights, and extends the page to its top gutter; ⌘L still opens the address command palette. ⌘← and ⌘→ navigate back and forward; the bracket aliases remain available. The shell never draws replacement traffic-light buttons.

`app:quit` requests application quit separately from `window:close`. macOS closes the native window after existing beforeunload decisions, releases its native contents, and retains the process for Dock activation. Reopening rebuilds the shell and restores session metadata. It does not promise that an approved window close preserves a live page's in-memory draft. Pending quit intent is cancelled when a page's close decision is cancelled. OS web-link events are validated and queued until a window can accept them. Menu editing commands target the focused web contents, including the active native page.


## Managed extensions and synchronization

`src/main/extensions/host.cjs` owns the manager, authenticated native bridge and browser API adapter. `browser.cjs` maps only browser tabs to their stable native WebContents IDs; inactive restored tabs have inert views without eager navigation. Idle sleep discards the document through blank navigation while retaining its native ID; explicit Close destroys the native page and closed pins are excluded from extension tab APIs. Waking a sleeping tab loads a fresh document. Blank reservations are not loaded pages for AI extraction or archive eligibility. `tab:extension-page` is an internal store action unavailable through shell IPC. Extension snapshots are projections without operational paths, secrets or settings values. Actual host APIs and lifecycle boundaries are documented in [Extensions](EXTENSIONS.md).

The shell's narrow `extension:*` actions cover installation/review, enable/remove, action/options, updates/rollback and permission reduction. `sync:*` actions are handled by `src/main/sync/controller.cjs` after shell-origin validation and active-profile checks. The controller owns `SyncClient`, OS credential protection and safe status projection. Registration/recovery explicitly return one-time recovery codes; routine state never does. The renderer's `sync.js` implements account/device controls, profile review, separate settings consent and rejected-change handling. Profile changes dismiss stale dialogs.

`SyncClient` persists local sync values and its outbox transactionally, bound to endpoint/account/profile/link generations. The host resolves storage callers from native contexts, never renderer-supplied identity. Event delivery rechecks current access and originating account/link epoch. Remote library intent cannot approve local permissions. See [sync setup and behavior](SYNC.md) and [the service HTTP contract](../services/sync/README.md#http-contract). The service remains outside desktop packaging.

## Restored tab navigation

Live web tabs retain a bounded `navigationHistory` containing HTTP(S) URLs, titles and the active index. Closing an ordinary tab carries this through the archive; session restart and idle wake restore both back and forward destinations through Electron NavigationHistory before loading the selected entry. Chromium page-state blobs, form values and POST bodies are not persisted; restoration reloads documents and does not promise to resume a submitted form. Private profiles remain excluded from persisted state. Portable exports/imports exclude navigation history, and clearing profile history removes the saved stacks. Explicitly closing a Favorite or pin continues to reset it to its saved destination.

## Gesture ownership and palette handoff

The trusted shell receives `space:gesture-phase` events from Electron's native `input-event` scroll/contact and fling phases. A wheel accepted by sidebar navigation claims the contact; page content, toolbar fields and editors do not. Held contact has no elapsed-time snap. A short flick selects one adjacent Space; sustained movement tracks across multiple Spaces and release snaps to the page reached by direct movement. Momentum deltas are ignored and velocity never projects the final destination beyond that movement. Platforms without phase signals retain the bounded quiet-period heuristic. Native contact signals take precedence over default DOM wheel momentum fields.

For command overlays, the native page stays visible until the renderer decodes and paints its captured replacement and acknowledges the matching `page:backdrop-ready` generation. Context/geometry changes invalidate the capture; a bounded timeout still releases the native view if capture cannot complete. Private pages are never captured. Sidebar metadata updates retain the drag source and targets until drop/end, while deleting the source or changing profile/Space invalidates that ownership. Dragging through Favorites opens an insertion placeholder and reflows neighboring tiles using their final balanced grid widths. The native source node stays connected; cancel restores the original layout and only drop changes the persisted order.

## Saved split groups

`splitGroups` stores `{id, spaceId, tabIds:[leftId,rightId]}` independently from the currently visible pair. Selecting an unrelated tab or Space hides the pair without removing its sidebar group. Selecting either member restores both panes; session restart and portable export/import preserve their association. Multiple groups can coexist, each within one profile and owning Space. Favorites may remain shared in other Spaces while the split belongs to its saved Space.

`split:toggle {id?}` creates a pair or removes the active group when called without an ID; `split:unsplit {id?}` removes the group containing a specified member without closing either page. Group members are excluded from automatic tab archival. Moving a member to another Space moves its partner and group together. Explicitly closing/removing a member dissolves the now-incomplete pair; profile deletion and malformed saved data cannot leave cross-profile or dangling group references. Saved groups remain available, dormant, even when ordinary session restoration is disabled.

## Window appearance

macOS uses an alpha-capable window with direct CSS tint opacity across 0–100, without a native vibrancy layer imposing a fixed opacity floor. Only background layers fade: text and website content remain opaque. The empty content canvas shares the window material. The Space editor preview uses the same gradient, tint alpha, grain and readable foreground tokens; visible desktop colors naturally depend on the background behind the actual window. Space accents also color folder icons, labels and sidebar details.

## Saved Peek destinations

Each open source tab may retain `savedPeek: {url,title}`. The host-only `peek:set {sourceTabId,url,title?}` mutation validates HTTP(S) destinations; `url:null` clears the association. Selecting another tab or Space detaches the preview view without unloading its document, preserving drafts, scroll position and its live back/forward stack. Returning to the source presents that same native page. Restart restores the saved destination on selection, loading a fresh document; no form data or preview page-state is written to disk.

Each source can own one preview. Explicit dismissal, expansion into a full tab, replacing the preview, or closing its source clears the association after any native beforeunload decision. Source tabs with a saved Peek are excluded from automatic archival and survive disabled ordinary-session restoration. Closing the window checks both visible and parked preview documents while retaining regular destination metadata. Private previews never enter persistent state or portable exports. Profile deletion disposes all its parked native pages before removing its data.

## Peek layering and saved site icons

Peek uses a transparent native sibling renderer above live source pages and below the preview document. Its local overlay has a narrow bridge for close, expand, retry and sidebar reveal, bound to the current Peek ID and its own main frame. Outside clicks are intercepted by this overlay. Browser dialogs capture the composed source, tint/controls and preview layers (up to four images for a split), then hide the native views after decoding; dismissal restores the same living documents.

Saved pin, Favorite and Peek destinations retain validated, bounded raster icons in local profile-and-URL-keyed files. A bounded memory cache speeds lookup without evicting disk icons for other saved destinations. Icons survive offline restart and failed refreshes, are excluded from portable exports and private-profile disk state, and are removed when the saved destination or profile is removed.

The toolbar pane glyph hides the sidebar. With the sidebar hidden, a 32px native floating pane button remains above the page at its top-left gutter; no address strip is reserved. It also appears beside Peek when its sidebar is hidden. Browser dialogs temporarily hide this reveal control.
