# Zacro interface and motion

The 0.6 interface builds on the earlier [Arc reference and workflow review](DESIGN-REVIEW-0.4.md). Navigation and the address field live inside the sidebar, leaving the page free of a permanent full-width toolbar. The sidebar order is navigation, address, icon favorites, Space identity, folders, a quiet New Tab row, and ordinary tabs. Its footer contains Library, Space indicators and a creation menu. Page actions and secondary tools live in compact menus. Library groups bookmarks, history, downloads, and archived tabs; Settings uses expandable groups.

The default sidebar is 224px wide; existing saved custom widths remain intact. Comfortable tab rows are 32px high and Compact rows are 28px; the footer is 32px. A raised selected row and hover/focus controls keep other tabs visually quiet, with 16px favicons and readable text. Page inset is configurable from 4–20px, defaulting to 8px, with matching left/right/bottom gutters. macOS and full screen use that inset at the top too; Windows reserves 36px for its window controls, and hidden-sidebar navigation or Find reserves 40px. Corner radius is configurable from square to 20px, defaulting to 12px. The shell, panel frame and native Chromium bounds/radii share these settings for normal pages, split view and Peek; split panes keep their 6px internal separator.

An empty Space opens the command palette without inserting a blank tab. New Tab and Ctrl/Command + T open the same palette; submitting a destination creates a page, while dismissal leaves the tab collection unchanged. Ctrl/Command + L edits the current address. The explicit New Tab Page action opens the home page with search, saved destinations, and recent pages. Pinned pages are omitted from home shortcuts while the sidebar is visible. The crossed-Z icon remains an original vector asset; system fonts use real weight variants.

Each Space has one of twelve built-in icons plus primary and secondary colors, gradient balance, grain, glass opacity and blur. Customize Space previews edits locally before Save; dismissal restores the saved theme. Glass blends the Space colors in browser chrome. Reduced transparency suppresses glass effects, and increased contrast/forced colors preserve distinct controls. Layout & motion also offers tab density, motion speed and idle-favorite timing.

Ctrl/Command + S toggles the sidebar; Ctrl/Command + Shift + S saves the page. A compact navigation row appears above the page when the sidebar is hidden, preserving the address and sidebar toggle. A 240ms spring at Balanced motion samples both shell width and native page geometry together, including a small rebound. Rapid reversal starts from the current presented width; reduced motion settles immediately. Pages remain live without reloading or being replaced by screenshots. There is no edge-hover panel. Ordinary profile details live in the Space switcher; private browsing remains explicitly identified.

Scroll horizontally over the sidebar to move between Spaces in the current profile, or hold Shift while using a vertical mouse wheel. During contact, the tab list tracks displacement and identifies the neighboring Space. The 0.6 recognizer decides on release, replacing the earlier immediate 64px trigger: a drag across 42% of the sidebar width or a qualifying velocity-projected flick commits one switch. Direction reversals unwind displacement and can cancel commitment. Endpoints use bounded rubber-band feedback without wrapping. Horizontal intent locks after a small movement; vertical scrolling and diagonal noise cannot become navigation through a sideways momentum tail. Webpage scrolling is unaffected. Each Space remembers its tab-list position.

One uninterrupted wheel stream can commit only once. Explicit contact-end/momentum hints are used when supplied. Without portable native phases, a 110ms pause or conservative sustained deceleration identifies likely release; 240ms of quiet rearms the gesture. These remain heuristics requiring physical-trackpad acceptance on supported Mac versions. Committed gestures settle from their actual displacement over a distance/speed-dependent 140–240ms interval at Balanced motion; cancelled gestures return over 100–200ms. Keyboard and direct Space changes use a 220ms transition. The command palette leaves the sidebar interactive; other dialogs, text inputs, tab dragging, pinch/zoom, pointer exit and window resizing interrupt tracking. A cancelled gesture consumes its remaining tail.

Windows High Contrast uses system colors, explicit selection/focus outlines, native checkboxes and named Space-color choices. Decorative artwork and blurred page backdrops are omitted in forced-colors mode so controls remain distinct.

macOS uses native traffic lights and a native menu bar. The title area reserves the controls' space with the sidebar shown or hidden; full screen removes that reservation until the controls return. The interface uses familiar ⌃⌥⇧⌘ labels, system typography, inactive-window treatment, Finder wording, and system contrast/transparency preferences. ⌘Tab and ⌘H retain their operating-system actions; ⌃Tab traverses recent tabs within the current profile. Close Window and Quit are distinct, with Dock reopening and private-session cleanup. See [the Mac guide](MACOS.md) for the full behavior and verification boundary.

## Motion rules

- Motion uses different timings for different interactions. At Balanced speed, entrances take 140–160ms, microfeedback takes 100–120ms, keyboard Space changes take 220ms, and the sidebar spring takes 240ms. Gesture settling follows the remaining distance and recent speed. Quick, Balanced, Relaxed and Gentle settings scale presentation; reduced motion overrides them. The old blanket 170ms ceiling does not describe the 0.6 motion system.
- Tab creation, selection, reordering, and folder disclosure use short local movement. Space changes keep their direction and continue from the presented gesture offset. Panels and dialogs enter with restrained opacity and translation; Peek's controls fade in over 120ms. Ordinary layout changes apply immediately; the sidebar spring synchronizes native geometry with each width sample. Focus and controls do not wait for an entrance to finish.
- Dismissal releases panels and modal surfaces immediately, restoring the live page and focus without waiting for an exit animation. Avoid long fades, large travel distances, repeated animation on metadata updates, and transitions that animate the contents of a live web page.
- State updates reuse unchanged UI sections, preserving focus, search input, scroll position, and ongoing animations.
- Native web pages are laid out only when geometry or visibility actually changes. Ordinary title, history, download, or icon updates must not hide/show an already visible page. Inactive pages detach from the native window hierarchy while their live documents remain available, keeping hidden pages out of platform accessibility navigation without discarding drafts. Modal backdrop capture briefly retains its hidden native surface until capture completes or the 750 ms deadline expires; the command input receives focus immediately. The longer image deadline accommodates cold native compositor copies without delaying the overlay or keyboard interaction.
- `prefers-reduced-motion` disables decorative and transition motion. Switching the preference while a dialog or panel is moving completes its finite transition and focus cleanup. No essential information is communicated only by animation.

## Interaction requirements

The command field follows combobox/listbox keyboard behavior. Results can be filtered to Tabs, Spaces, Bookmarks, History or Actions; `/` and `>` select actions, `@` selects tabs and `#` selects Spaces. Fuzzy matching uses names, descriptions and action keywords. Actions expose Space customization, sleeping unused favorites and prepared AI intents alongside normal browser commands. IME composition must finish before Enter can navigate or send a question. Forms and other modal dialogs isolate background controls, trap Tab, and restore focus to a usable trigger when dismissed. The command palette keeps the sidebar available for tab, Space and navigation actions while protecting the live page behind its backdrop. Its query and results are cleared when the profile changes. Panel searches retain their input and selection during state updates. F6 moves between the web page and browser controls. Split-view navigation and page actions target the focused pane without swapping page positions. Compact menus preserve tooltips, accessible names and keyboard access; secondary tab controls appear on keyboard focus as well as hover.

The shortcut catalog drives host input, native menus, command search and the searchable shortcut editor. Defaults follow Arc's [command and recent-tab model](https://start.arc.net/master-multitasking): Ctrl/Command + T opens commands, Ctrl/Command + D pins, and Ctrl + Tab visits recent tabs. Holding Control freezes the recent-tab order until released; sidebar-order navigation uses pinned tabs, folders and ordinary tabs. Ctrl/Command + Option/Alt + Left/Right switches Spaces, and Control + 1–9 on Mac or Alt + 1–9 on Windows selects a Space directly. Rebinding removes a command's old aliases; resetting validates restored aliases before accepting them. Platform-specific overrides survive restart. The editor preserves system/editing combinations, IME input and AltGr text entry.

The sidebar shortcut keeps focus in the active web-page field when invoked there. A toolbar click keeps focus on the toggle so its next action is predictable. Library panels return to the Library opener, and switching Library sections does not lose that return target. Settings disclosures retain their expanded state and input drafts through asynchronous updates.

Manual tab names survive web-page title changes, reloads, and restarts. A page preview keeps its JavaScript state, input, and scroll position when promoted. User-written form state is protected by the existing beforeunload decisions.

Closing a favorite keeps its name, address and position, marks it Closed and releases its native page after any unsaved-work decision. Activating it opens a fresh page. Loaded and Sleeping favorites have distinct status too. Idle favorites can sleep after a configurable interval, defaulting to 20 minutes, or through an explicit action. Active/split/Peek-source pages, media/capture, pending authentication, downloads and detected edits block sleeping. An isolated DOM inspection conservatively keeps changed fields, editing surfaces and unreadable frames awake; beforeunload vetoes automatic unloading silently. Sleeping discards runtime state and reloads on activation, so protections do not imply that every website's arbitrary in-memory state can be detected.

AI starters prepare summaries, explanations, comparisons or research questions without sending. Context chips identify the explicitly granted document titles/URLs; selecting another active tab does not change them. A navigated/closed document requires review or removal before the next send, and backend history scopes include document URLs. Each user turn records its context. Edit restores a request for review; Retry sends only on a deliberate click; Copy includes answer text, warnings and returned sources. Drafts survive panel changes, streams and retries within a profile, including hidden-panel handling, but do not cross profiles. Enter sends and Shift+Enter adds a line. Partial answers remain marked incomplete, and request IDs prevent a cancelled/reset turn from reappearing. See [AI.md](AI.md) for provider limits and data boundaries.

## Reproducible review

`npm run test:interactive` launches the browser with a fresh disposable profile and a local journal fixture. Add `-- --showcase` for a populated design-review workspace, or `-- --packaged --showcase` to inspect the packaged executable. The showcase uses prepared demo tabs and bookmarks; only the local active page loads initially. Its Mail, Calendar, Notes and Studio favorites open local demo pages with original PNG icons; visit each once to load those icons through Chromium. The fixture includes navigation, a second article, a page-local draft/counter, popup links, and a small download. Close the browser when finished; the launcher removes only its own temporary profile. A manually downloaded test file uses the browser's normal Downloads directory.

`npm run test:e2e` checks real Chromium interactions, focus restoration, sampled text contrast in light/dark themes, reduced motion, responsive layout, native page bounds, and profile boundaries. `npm run test:soak` repeats tab/Peek/split lifecycles, verifies that closed native pages are released and the original draft/reading position survives, and writes resource observations to `test-results/soak.json`. These checks supplement hands-on Windows review; they do not replace a full assistive-technology, real-site, or long-running performance evaluation.
