# Optional AI connections

Browsing does not require AI. Settings offers six separate connections:

| Connection | Authentication | Questions and page/PDF context | Web research |
| --- | --- | --- | --- |
| ChatGPT subscription | Bundled official Codex app-server; your own ChatGPT sign-in | Yes | Hosted Codex search |
| Claude subscription | Installed official native Claude Code CLI; your own Claude sign-in | Yes | Not enabled in this integration |
| OpenAI API | Your OpenAI API key; Responses API | Yes | Hosted web search |
| Claude API | Your Anthropic API key; Messages API | Yes | Hosted basic web search, up to five searches per request |
| OpenRouter | Your OpenRouter API key; Chat Completions API | Yes | OpenRouter web plugin |
| OpenAI-compatible API | Your configured model and API base URL; Chat Completions API | Yes, subject to server compatibility | Not assumed or enabled |

Subscription access and API billing are separate. Zacro never silently switches providers, subscriptions, models, or keys after failure. API requests and hosted search can incur charges with the selected provider. Account eligibility, model access, limits, and provider terms still apply. Model IDs are configurable; defaults do not guarantee access. **Test saved connection** checks a model catalog or account metadata endpoint without inference. A successful metadata check does not prove a particular model or search feature is available.

## Sign-in and credential storage

**ChatGPT:** Finish the official sign-in in your system browser. Zacro uses a separate `CODEX_HOME` and never imports a developer's Codex setup or tokens. The default is the OS keychain/keyring. A `persist_failed`, missing default keychain, or storage failure clears the transient account and displays `AUTH_STORAGE`. Zacro does not report success or write a plaintext `auth.json` fallback. Unlock/create your default OS login keychain and retry, or explicitly choose **This session only**. This uses Codex's supported `ephemeral` credential mode; sign-in ends when its runtime stops, including app exit or connection restart. Switching an active keychain connection to session-only first invokes official logout. If the keychain/runtime was unavailable, an earlier durable sign-in may remain; switch back to keychain storage and Sign out to remove it.

**Claude subscription:** Install the official native Claude Code CLI through the linked provider instructions (minimum 2.1.259). Zacro discovers native executables in standard installation/PATH locations, without automatic installation or shell wrappers. Official CLI login/status/logout commands run with a separate Zacro `CLAUDE_CONFIG_DIR`. The CLI handles OAuth; Zacro never extracts or replays subscription tokens. The provider manages storage: macOS Keychain when available, a local credential file on Windows/Linux, and a local file fallback when macOS Keychain rejects a write. This is disclosed before sign-in. Browser-callback login is supported; a remote environment requiring manual terminal code entry needs the provider's terminal workflow instead. Personal terminal sessions are not imported.

**API keys:** Only the trusted application bridge accepts keys; they remain in the main process. Durable storage uses Electron's asynchronous `safeStorage` on Windows and macOS. Opening the browser or reading connection status never initializes the credential store; only an explicit encrypted-key operation can request OS access. Unavailable or locked storage fails closed, and a timed-out operation cannot later save a key. Linux currently requires explicit session-only storage because the asynchronous provider can fall back to a local key without exposing its security level. No plaintext fallback is used. Explicit **This session only** keeps the key in memory and removes a previous durable key for that connection. Changing storage with an empty key field converts the existing key if decryptable; unreadable encrypted files are preserved. Legacy credential files are not imported.

API keys and configuration belong to a browser profile, provider, and exact normalized endpoint. An endpoint edit never forwards an existing key to a new server. Profile deletion removes its API credentials, including old endpoint bindings, configuration and conversation. Subscription sign-ins are app-level connections with separate provider homes; deleting a profile does not sign out subscriptions used by other profiles. Disconnect removes the selected provider connection and clears conversations. This does not promise forensic erasure from backups or storage media.

The renderer receives connection status, safe account/model metadata and notices, never keys or tokens. Raw provider diagnostics and error bodies are not logged or exposed. Credentials do not enter browsing-state exports.

## Questions, sources and context

- **Starting actions:** Summarize page, Explain page, Compare tabs and Research prepare an editable question and context. They do not send an inference request. Existing unfinished questions are preserved instead of being replaced by a starter. The command palette offers the same actions.
- **Before connecting:** The question and selected-page chips remain visible and editable. Connect AI opens Settings without discarding that work; sending stays disabled until a connection is available. Preparing a question does not extract page content or contact an inference endpoint. A different question submitted from the palette is held in a Saved question card for review instead of replacing an unfinished draft; if that slot is already occupied, the new question stays in the palette.
- **Research:** Supported providers enable their hosted search without attaching open pages, history, cookies, passwords or downloads. Claude subscription and compatible connections answer general questions with an explicit no-web-research notice.
- **Sources:** Only structured provider results/citation annotations establish research URLs. Model-written links alone are not verified sources. Citations are visible and clickable. A page citation reuses its existing tab only if that tab still shows the cited document; otherwise it opens the cited URL separately. Paragraph citations can locate quoted text; PDF citations identify the physical page. A separate action opens bounded HTTP(S) sources after an answer completes. Missing evidence produces a warning; a returned URL does not prove every claim.
- **Pages/PDFs:** Explicitly select one page or up to six tabs in the current profile. Context chips show the chosen titles and hosts, with the exact URLs in their tooltips. Switching to another active tab does not change this selection. If a selected tab navigates or closes, sending is disabled until its context is reviewed or removed. The main process checks the granted URLs before and after extraction. Extracts are capped at 20,000 characters each and 60,000 total. Search is disabled. Answers can cite actual paragraphs and physical PDF pages. Empty/unreadable context produces an error rather than silently becoming research.
- **Comparison:** Choose two to six pages, review their chips, and send the prepared comparison question or write your own. Only checked pages are shared. The answer identifies unreadable pages and partial extracts; it cannot establish facts absent from the provided text.
- **Follow-ups:** Main-process memory holds at most eight turns and 160,000 serialized characters per profile/context scope. The scope includes document URLs as well as tab IDs, so a navigated tab cannot silently inherit the old document's conversation. Provider/configuration and page/research scope changes clear incompatible context. Clearing context or starting a new conversation removes the previous conversation and page selection while retaining an unfinished composer draft. Anthropic's opaque search blocks are preserved for follow-ups. App exit discards conversations.
- **Drafts and recovery:** The composer keeps an in-memory draft across panel switches, streaming updates and retries, and clears it when switching browser profiles. Enter sends; Shift+Enter adds a line, and IME composition does not submit. Edit question restores a prior question and its still-valid page selection into a new conversation, without sending; it does not overwrite a different unfinished draft. Retry question explicitly resends a failed or stopped question and may incur provider usage. There are no automatic inference retries. Copy answer writes plain text, any warning, and returned source links to the clipboard.
- **Download names:** Suggestions share filename, source URL and page title only, without reading the file. Sanitization preserves the extension; the host handles collisions and undo.
- **Stop:** Cancellation interrupts/kills the owned runtime or aborts HTTP. Partial text remains marked incomplete, with recovery controls. Turn events carry a request identifier so a late result cannot reappear in a reset conversation. Answer requests have a two-minute deadline. Cancellation cannot retract already-transmitted data or guarantee no usage charge.

Private profiles are excluded. Tab ownership and active profile are checked before extraction/transmission and before publication. Provider changes are blocked during requests. Page text and search results are evidence, never permission to act.

Web text extraction runs in an isolated JavaScript world without form controls, editable surfaces or hidden content. Visible text can still contain personal information. Explicitly selected remote PDFs are fetched through their browser profile. PDF.js extracts static text locally in a worker: 20 MB input, 100 pages/60,000 characters, 20 seconds, bounded heap. It does not execute PDF actions, read form annotations, follow links or upload raw files. Password-protected/image-only PDFs are rejected; there is no OCR. Text order/font extraction can be imperfect and truncation is identified.

## Runtime and network restrictions

Codex uses private stdio, an empty Zacro-owned workspace, disabled project discovery, ephemeral threads, disabled history/analytics, no execution environments, read-only sandbox and never-approve policy. Shell/file/browser/computer tools, plugins, memory and additional agents are disabled. Discovered skills are disabled; MCP inventory or skill-discovery failures reject the connection. Unexpected tools/approvals terminate the runtime. Search is only enabled for research. Its pinned experimental protocol needs review before upgrades.

Claude Code runs in safe/restricted mode with no user/project settings, disabled hooks/auto-memory, empty strict MCP configuration, denied MCP tools, empty built-in tools, no permission prompts/Chrome integration/persisted sessions, and one answer turn. Prompts go over stdin. Its minimum version supports these controls. The environment excludes inherited API/OAuth credentials, custom endpoints, runtime injection and shell startup configuration. The CLI owns login and may retain operational records; Zacro makes no blanket provider-retention claim.

API calls originate in the main process. OpenAI, Anthropic and OpenRouter have fixed official endpoints. Custom endpoints require HTTPS; HTTP is permitted only on localhost/loopback. Embedded URL credentials, query strings and fragments are rejected. Requests omit cookies and reject redirects so credentials are not forwarded. JSON bodies are bounded to 2 MiB, including chunked responses; cancellation and error/size/type failures close bodies. Output is bounded to 4,096 tokens. OpenAI sets `store: false`, not a blanket retention guarantee. OpenRouter provider fallback is disabled. No client tools execute.

## Validation and remaining acceptance

Tests cover encrypted/session storage, endpoint/profile isolation, keychain persistence failure, cancellation, body bounds, citations, CLI restrictions, account state and consent through controlled transports. The actual bundled Codex 0.164.0 completes an isolated **ephemeral-auth** signed-out handshake without inference or `auth.json`. Tests do not read personal credentials, finish sign-ins, or make paid inference calls. Claude CLI uses a controlled process transport in tests; live install/sign-in remains an acceptance check.

Local-provider workflow tests exercise real page extraction, selected-page comparison, explicit URL review after navigation, draft retention, edit/retry/stop, source copying and rejection of late answer events. Separate regressions cover streamed composer focus/IME behavior and backend conversation isolation when the URL changes inside an existing tab. These fixtures do not establish live-provider answer quality or sign-in availability.

Before distribution, verify actual ChatGPT/Claude sign-in on each OS, model access, limits/billing, answers/search citations, cancellation and packaged executable discovery. Provider account/commercial terms still apply. Anthropic currently permits products to host the unmodified Claude Code binary under its commercial terms and end users to use their own subscriptions; this does not authorize OAuth extraction, credential resale or shared subscription intermediation. OpenAI's supported commercial authentication/distribution requirements must also be reviewed before paid/hosted release.

Raw uploads, OCR, password unlocking, selected-text questions, form preparation, consequential browser actions, semantic history search and recurring tasks remain unimplemented. Protected/unloaded pages may lack readable text; Ask Peek requires tab promotion. These connections do not implement every proposed README feature.
